# F7.2 — Employee Clocking Backend Foundation

Status: **READY FOR PRODUCT OWNER REVIEW**. Backend foundation only; no frontend implementation. Not committed or pushed. Verified 8 October 2026.

## Contract and impact assessment

The existing D9 AttendanceEvent model is immutable observation evidence. Its caller-timestamped HR intake is not suitable for employee clocking. D10 supplies authenticated account-to-Employee linkage and the existing SelfService capability. D12 employment/account rules and Employee-first locking remain authoritative. D9 daily calculations, HR corrections, reopening, source fingerprints and immutable finalization remain unchanged.

This implementation adds server-stamped EmployeeClock evidence and a small session table. It does not replace legacy evidence, classify legacy records, change existing attendance request contracts, modify payroll formulas or add role/capability grants. OnCampus, OnlineClass and RemoteWork are employee-reported work arrangements, not verified location or pay entitlement. All locations are permitted; no GPS, IP restrictions, webcam or schedule prerequisite is introduced.

## Architecture and endpoints

EmployeeClockController → IEmployeeClockService → EmployeeClockService → EF Core. The controller never uses DbContext. All endpoints require the existing SelfService capability and a valid authenticated User → Employee link, independently rechecked inside the service. SystemAdmin/HR/Payroll privileges alone do not grant employee clocking.

| Method | Endpoint | Behavior |
| --- | --- | --- |
| POST | `/api/self/attendance/clock-in` | Open own session; 201 first acceptance, 200 identical retry |
| POST | `/api/self/attendance/clock-out` | Close own specified open session; 201 first acceptance, 200 identical retry |
| GET | `/api/self/attendance/current` | Own open session, or HTTP 200 JSON null |
| GET | `/api/self/attendance/sessions` | Own paged history; optional inclusive opening-date `from`/`to`, page default 1, pageSize default 20, maximum 100 |

Clock-in body:

```json
{ "requestKey": "<new GUID retained for retries>", "workArrangement": "OnlineClass" }
```

Clock-out body:

```json
{ "requestKey": "<new GUID retained for retries>", "sessionId": "<own open session GUID>" }
```

Unknown request fields are rejected, including supplied employee/actor/source/timestamp fields. Numeric or unknown work arrangements and empty GUIDs are invalid. DTOs expose session ID, arrangement, IN/OUT evidence IDs, UTC instants, Bangkok business dates/time zone and IsOpen. Command results additionally expose IsReplay. Swagger response metadata documents the four operations.

Errors: 400 malformed/invalid/ineligible employment or missing/invalid CSRF; 401 unauthenticated; 403 missing capability/linkage; 404 OUT session not owned/open; 409 conflicting state/request-key payload or nonadvancing server clock. CSRF rejection uses the existing security response. No sensitive coworker information is returned.

## Persistence and migration

Migration: `20261008061002_AddEmployeeClockingFoundation`.

**Generated and applied successfully only to disposable localhost test databases. Not applied to Development SIAMIS or Production.** No test attendance, users or operational fixtures were created in SIAMIS. The existing Development API remains running on its previous binary; deploy the reviewed migration and new binary together before using these endpoints in that application.

EmployeeClockSessions columns: Id, EmployeeId, WorkArrangement, InEventId and nullable OutEventId. Instants and actor attribution live on the referenced immutable AttendanceEvents, avoiding duplicated timestamps.

- Filtered unique EmployeeId index where OutEventId is null guarantees at most one open session.
- Unique IN and non-null OUT event indexes prevent reuse within session links.
- Composite event foreign keys enforce matching employee ownership, using a new `(EmployeeId, AttendanceEventId)` alternate key.
- Employee and event foreign keys use NoAction; no cascade deletion.
- Arrangement check accepts exactly OnCampus, OnlineClass and RemoteWork; binary collation enforces stored spelling.
- Check rejects identical IN/OUT IDs.
- AttendanceEvent source constraints add EmployeeClock while retaining the existing ManualAuthorized/Device/Imported branches. Clock evidence requires direction, actor, source/request identifiers, Ready employment, active-at-capture state, equal server occurrence/receipt timestamps and no caller original timestamp/manual reason.
- No seed data or historical backfill.

Existing datetime2(7) evidence preserves exact UTC ticks. Session opening provenance is immutable; only one null-to-OUT closure is permitted by the DbContext guard. Existing immutable AttendanceEvent protection and SecurityAuditEvents attribution apply atomically. This follows existing application immutability conventions; privileged direct SQL administrators are not constrained by the EF mutation guard. Database checks protect ownership, arrangement and open-session uniqueness, while service validation protects direction/source/closure semantics.

Migration Down is not a record-cleanup mechanism: restoring the old source constraint after clock evidence exists requires a separately reviewed retention/rollback plan.

## Validation, concurrency and idempotency

Commands use Serializable transactions and existing canonical Employee → role guard → account locking. Account activity, forced-password-change state, current linkage and real role-derived SelfService capability are rechecked under lock. Employee must be active with exactly one valid effective, current, open EmploymentRecord and active non-terminal employment status/context. No calendar assignment is required to record actual evidence.

The server captures UTC after locks are acquired. It never accepts or synthesizes a claimed clock time. Identical/nonadvancing timestamps relative to previous employee clock evidence produce 409; deployment requires a correctly synchronized server clock.

RequestKey is scoped to the linked employee across both directions. An identical accepted command replays without another event, timestamp, session or audit write. Reuse for another direction, arrangement or session produces 409. Replay retains original evidence but returns the session's current closure state. OUT requires the explicit SessionId so a delayed command cannot close a newer session. Concurrent same-key submissions create once and replay; competing different-key IN commands allow only one open session. Transient deadlock/uniqueness/concurrency conflicts return 409 for retry with the same key. Ordinary unexpected persistence failures remain server errors and rollback the transaction.

Reads use AsNoTracking, database ownership filtering, ordering, counting and bounded pagination. Fresh account/linkage authorization is also locked for consistent read ownership.

## Attendance review and historical behavior

New evidence naturally enters the existing D9 daily calculation and source fingerprint. A source change after finalization marks the previous revision stale/requires reopen on existing review reads; it does not rewrite, reopen or refinalize automatically. HR uses existing reasoned reopening/corrections/adjudications under existing capabilities. SelfService cannot access HR review commands.

Missing OUT is incomplete evidence, not misconduct or a deduction. No timeout auto-closes a session. HR corrections append separate evidence and preserve original clock events; they do not silently close/relink an employee capture session. A later employee OUT records actual current time, not a backdated HR correction. A dedicated administrative session-resolution or employee correction-request workflow remains a separate contract extension.

Cross-midnight sessions can retain actual IN and OUT business dates. Existing D9 same-day pairing is deliberately unchanged: those daily records may show missing IN/OUT findings and require HR review. No overnight split, guessed midnight timestamp or automatic entitlement is added. An open session is not equivalent to finalized attendance or a confirmed “working now” status.

No clock, missing-OUT, correction or stale-state operation invokes Payroll, Leave balances, KPI or disciplinary logic. Payroll calculation/generation/preview and lifecycle code are unchanged.

## Frontend integration requirements — deferred

1. Use the real authenticated session and SelfService capability; never accept EmployeeId as ownership.
2. Use the existing API client/CSRF flow; generate one RequestKey per intended action and retain it across network retries.
3. IN selects a work arrangement. OUT uses the session returned by current/read, with a new key.
4. Refresh own current/history after success or conflicts; do not optimistically invent accepted timestamps.
5. Format returned UTC instants explicitly using Asia/Bangkok. Date filters refer to session opening business dates.
6. Clearly distinguish missing OUT/open capture, review findings and finalized attendance. Provide existing HR review pathways without automatic penalties.
7. Preserve secure failure handling and account/employment restrictions. No offline backdated clock submission.

No frontend clocking UI, GPS, camera, Leave management, payroll changes or additional authorization grants were implemented.
