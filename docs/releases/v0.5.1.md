## Implemented features

- Premium V3 platform-wide components, shell, authentication and responsive HR workspaces.
- Real capability-filtered HR Dashboard, Employee Directory/360, supporting contact/address/emergency records, employment and account lifecycle.
- Passwordless User Accounts provisioning and secure activation through existing D13 contracts; employee registration remains separate.
- Automatic immutable employee numbers from 100000, concurrency-safe SQL allocation and permanent non-reuse reservations; legacy GUIDs/numbers retained.
- Private employee JPEG/PNG photos with decoded-content validation, 5 MiB/4096 × 4096 limits, authenticated retrieval, audited version changes and initials fallback.
- Exceptional permanent deletion for eligible mistaken registrations, with explicit capability, protected-dependency checks, identity confirmation and preserved reservations/audit. End Employment remains normal offboarding.
- Registration idempotency: actor/operation-scoped durable receipts, atomic completion, safe concurrent/lost-response replay and payload-conflict responses.
- Attendance evidence/review/corrections, explicit reopening/finalized history and employee-owned server-timestamped clock sessions. On Campus, Online Class and Remote Work are supported without location surveillance.

See [HR status](../modules/hr/README.md) for detailed feature boundaries; frontend Leave/Payroll/HR-document operational modules are not claimed complete.

## Authentication lifecycle correction

Stage 1 preserves mounted pages and query state when focus/timer revalidation returns an unchanged security context. Changed identity/linkage/eligibility/roles/capabilities clears protected state. Transient authenticated probe failures preserve drafts only in RAM while a native modal blocks protected content and requests; retry restores access only after successful validation.

Initial offline `/login` remains available; protected initial loads remain fail-closed. Submission network failures remain in the login form without claiming invalid credentials. Request epochs prevent stale responses/CSRF-waiting mutations crossing session boundaries; logout invalidates pending refresh. No auth bypass, persisted credentials, backend endpoint or cookie/CSRF change was introduced. See [authentication contract](../frontend/AUTHENTICATION.md).

## Registration idempotency

Within 30 days, the same scoped key and equivalent committed payload returns the original successful result without another employee number. Different payloads conflict. Expired keys retain permanent reuse protection and cannot create another employee. Uncommitted failures can retry; bounded lock waits do not leave indefinite pending records. Independent keys permit legitimate employees with similar details. Number gaps from rolled-back allocations remain allowed. See [F5.1E.1 architecture/tests](../frontend/F5.1E1-EMPLOYEE-REGISTRATION-IDEMPOTENCY.md).

## Frontend dependency repair

Node 22.23.2 / npm 10.9.8 exposed inconsistent AJV peer placement. The targeted lock repair places AJV 8.20.0 and json-schema-traverse 1.0.0 at root for the resolver peer, AJV 6.15.0 and json-schema-traverse 0.4.1 under ESLint, and fast-uri 3.1.8 for AJV 8. Relevant transitive flags were reconciled: three entries added, six changed, none removed. Direct dependency/framework versions and package.json remained unchanged.

No force/legacy-peer-deps override or peer-validation bypass was used. Unrelated bundled Tailwind WASM metadata generated by npm was excluded from the targeted repair. Required dry-run and genuine isolated clean installation passed; regressions ran against that installation. Main node_modules was not replaced.

## Known limitations and release gates

- Stage 4 final verification and owner review of commit scope/history remain outstanding. No clean-working-tree, tag, push or release claim is made.
- Raw screenshots, logs, identity snapshots and local evidence require privacy review before publication. Ignore rules do not untrack files or erase history.
- Production TLS/proxy trust, Data Protection keys, delivery provider, storage ACLs, malware scanning, coordinated backups and disaster recovery remain deployment responsibilities.
- Photo originals may retain EXIF; superseded/removed binaries are retained indefinitely. No automatic purge/reconciliation is provided.
- Receipt keys remain permanently protected; there is no scheduled expired-response purge or cross-tab registration recovery.
- Public legacy API AdminLTE landing page and superseded QA utility require owner disposition. No cleanup executes that utility.
- No automatic Attendance/Leave payroll deductions, GPS/webcam verification or disciplinary inference.
- Browser-tab persistence and full-reload draft recovery remain deferred.
- QR credentials, kiosk scanning and monthly timesheets are not implemented.
