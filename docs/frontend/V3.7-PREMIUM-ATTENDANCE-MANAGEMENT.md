## Existing workflow audit (recorded before edits)

- `/hr/attendance` uses the existing shell header. Daily overview requires Reporting.Read; review queue and evidence/history remain inside Attendance.Read routing.
- Daily reporting reads `/api/attendance/today` or `/api/attendance/days/{date}`. Review queue reads `/api/attendance/review-queue` with an explicit inclusive range. Existing URL filters and bounded 20-row pagination are authoritative; there is no unsupported global attendance search.
- Employee lookup uses Employee.Read. Employee history and summary require Reporting.Read; legacy attendance is read-only. A user without directory permission can supply an employee GUID, with backend authorization unchanged.
- Row inspection is a contextual drawer. Full review reads `/api/employees/{employeeId}/attendance-days/{date}/review`. Evidence list/detail and finalized history are separate read endpoints.
- Attendance.Manage exposes manual evidence, correction and inclusion/exclusion decisions. Attendance.Finalize exposes absence confirmation, finalization and reopening. Frozen revisions suppress corrections/adjudication/finalization until explicit reopening. Manual observations retain original evidence and can make a finalized revision stale.
- Commands use existing POST endpoints and reason validation. Workflow decisions freeze expectedVersion and expectedSourceFingerprint; manual evidence uses a request key. Conflict and pending behavior must remain unchanged.
- Original presentation leads with raw status codes, repeats readiness in large fact collections, has a technical ten-fact review introduction, and mixes correction/decision/finalization controls in one row. Evidence and frozen history are present but require clearer orientation.
- Initial live review is authenticated as qa-systemadmin. Development data has configuration-required days and empty evidence/history; live verification cannot prove populated mutation workflows. Those will use isolated tests.

1. Attendance Management header with factual context; the existing payroll boundary remains visible.

3. Labeled, contained filter toolbar; advanced factual filters stay in a disclosure. No new search endpoint or fabricated priority score.

5. Contextual 640px inspection drawer with separate live and currently validated facts, findings, changed sources and a stable full-review action footer.
6. Full review begins with concise day context, a text-based validity state and optional technical details. Evidence/decisions and finalization/reopening are distinct action groups.
7. Existing calculation, raw evidence, audit and immutable revisions remain separate tabs. Technical finding codes, grace-policy identifiers and precision metadata remain available in disclosures.

The presentation does not reorder the server queue or infer exclusive categories. Counts remain server totals before pagination. Missing configuration remains unavailable coverage, not zero work. Stale revisions remain historical evidence, never current validation or an HR violation.

## Employee Directory filter overlap correction — 9 October 2026

### Verified root cause

Reproduced with the real authenticated Directory at 1280×800. This was a shared CSS regression introduced by the row-subgrid toolbar: the outer FormField had `min-width: 0`, but its implicit grid column and inner control wrapper still used automatic intrinsic minimum sizing. A long selected label therefore expanded the inner column beyond the allocated outer cell. The existing selected-value ellipsis could not work until that containing column was allowed to shrink.

Employment Status measured **231.76px inside a 180.49px cell**, ending at x=897.51 while Employee Record started at x=862.24: approximately **35.28px of overlap**. Feature-specific legacy `.employee-filters` rules were not active on the new `.employee-filter-surface`; they were not the cause.

The earlier document-width checks did not detect internal cell overflow. This correction adds explicit live assertions for control containment within each cell and selected-text/chevron separation.

### Small shared correction

Only `frontend/src/app/styles/primitives.css` changed in application source:

- Constrain toolbar children with `min-width: 0` and `max-width: 100%`.
- Give the row-subgrid fields/actions an explicit **`minmax(0, 1fr)` column**, eliminating the automatic intrinsic column minimum.
- Set inner control wrappers to `min-width: 0; width: 100%`.
- Constrain toolbar controls to `width: 100%; max-width: 100%`.

The existing 16px column gaps, aligned label/control/helper rows, responsive auto-fit wrapping, 44px control height and selected-value ellipsis/chevron reservation remain intact. No filter options, controlled values, queries, search submission, pagination, ordering, capability gates or interaction handlers changed.

After correction, Employment Status and its trigger both measured **180.49px**, ending at x=846.24; Employee Record still began at x=862.24, leaving the intended **16px gap**.
