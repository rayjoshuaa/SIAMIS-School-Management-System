# F7.2 — Employee Clock In / Clock Out

> Historical proposal: the missing clocking contracts described below were subsequently implemented by approved F7.2 and integrated in the employee frontend. This document preserves the proposal, not a current unsupported-feature claim. See [current HR status](../modules/hr/README.md).

**Historical F7.1 discovery proposal.** The separately approved F7.2 backend foundation is now implemented; see [implementation and verification report](../development/F7.2-EMPLOYEE-CLOCKING-BACKEND.md). Frontend clocking UI and the additional correction-request/session-resolution extensions described below remain deferred. The original discovery findings below describe the pre-F7.2 baseline.

## Objective

Authenticated employee clock-in/out for on-campus work, online classes and remote work, employee-owned history and reasoned correction requests. Preserve the frozen D9 exact-time calculations, HR review, immutable finalization and payroll boundaries.

## Existing foundations and gaps

- D10 supplies an authenticated User → Employee linkage. Client-supplied EmployeeId is never proof of ownership.
- D9 stores immutable evidence with datetime2(7) occurrence times, server receipt timestamps and actor/provenance metadata.
- Existing manual intake requires Attendance.Manage and accepts caller-supplied OccurredAt. Server ReceivedAtUtc is intake metadata, not an authoritative employee clocking contract.
- Linked employees can already read their own calculated history/summary. SelfService does not authorize HR raw intake, review commands or organization-wide administration.
- No employee clock commands, server-stamped clock occurrence contract, on-campus/online-class/remote classification or employee correction-request workflow exists.
- HR append-only corrections/adjudications, reasoned finalization and reopening already exist. Do not repurpose them as employee commands by relaxing authorization.

## Proposed contract responsibilities

### Employee clock commands

Introduce narrowly scoped authenticated commands through a separately approved backend contract. Resolve Employee solely from the actor's existing linkage. Preserve sessions, CSRF, employment/account lifecycle checks and backend authorization. Reject missing/invalid linkage and cross-employee clocking safely.

The server should determine the accepted occurrence instant at clock receipt and persist it at existing exact tick precision. Normal clock requests must not accept editable occurrence time or actor identity. Backdated/offline claimed work requires a distinct reviewed correction process.

Responses should identify persisted evidence, direction, exact occurrence/receipt time, business date/time zone, approved work classification and neutral intake findings. Approve request-id idempotency, duplicate/concurrent-request handling and response codes before implementation. F7.1 does not invent endpoint names or expose unusable clock buttons.

### Work classification

Proposed contexts: On-campus, Online class and Remote work. These describe reported context; they do not prove location, authorization, productivity or pay entitlement.

Approve persistence, who selects/changes context, whether remote/online work needs prior approval and whether an OUT must reference its IN/context. If session linkage is required, approve that model explicitly. Never retroactively classify legacy evidence. Preserve unknown/not-recorded historical context and immutable provenance.

### Employee-owned reads

Reuse the existing history/summary ownership boundary. Additional clock/evidence/status reads must derive ownership from the actor, remain bounded/paged and exclude coworkers/HR-only decisions. Do not reinterpret the current D9 CurrentPresence = Unknown as “currently working” without an approved open-session algorithm.

### Missing OUT and correction requests

Missing OUT remains incomplete evidence, not automatic absence, misconduct, overtime or payroll deduction. Do not synthesize timestamps, automatically close sessions or guess cross-midnight behavior.

Propose an employee correction request with reason and claimed facts, separate from authoritative recorded evidence. HR acceptance should append approved correction/adjudication evidence, retaining original facts, requester/reviewer identities, decision reasons and timestamps. Approve request states, visibility, duplicate/rejection/cancellation handling and review-capability mapping first.

### HR audit and finalization

Preserve Attendance.Manage / Attendance.Finalize separation. New clock evidence must participate in deterministic source fingerprints and Employee-first locking/source-version protection. Source changes can make a finalized revision stale; they must not rewrite, automatically reopen or refinalize it. Explicit reasoned reopening preserves prior immutable revisions.

Use established authenticated auditing. Never accept client-provided actor IDs or add a parallel audit system. Approve any additional privacy/retention contract before extending storage.

## Decisions required before implementation

1. Exact command/read DTOs, endpoint names, status codes and ownership/capability policies.
2. Employment/date eligibility, multiple sessions, duplicate IN/OUT, cross-midnight work and unresolved previous OUT behavior.
3. Classification persistence/authorization and unclassified historical evidence handling.
4. Session linkage, idempotency and concurrency semantics.
5. Correction-request lifecycle and integration with HR review/source-version protection.
6. Focused schema/migration requirements, if necessary; this proposal approves or creates neither.
7. Deployment clock synchronization and the distinction between receipt evidence and claimed actual work time.

## Proposed verification

- Real authentication, CSRF and actor-derived ownership; cross-employee and organization access denied.
- Immutable server-generated occurrence timestamps; supplied/spoofed time or actor rejected.
- Approved duplicate/retry/concurrent IN/OUT semantics.
- All three work contexts, validation and historical provenance.
- Missing OUT, employee correction requests, HR decisions and audit history.
- Fingerprint changes, stale detection, explicit reopen and preserved finalized revisions.
- Exact tick/grace boundaries, minute-based Leave coverage and residual regressions.
- No payroll, Leave, KPI or disciplinary mutations.
- Accessible responsive employee UI and self-service route restrictions.

## Exclusions

No GPS, webcam monitoring, biometric/device integration, automatic payroll deduction, fake sessions, new role grants, guessed attendance policies, automatic clock-out or F8 implementation. F7.1 Attendance Administration remains the priority. Product-owner/backend contract approval is required before F7.2 implementation.
