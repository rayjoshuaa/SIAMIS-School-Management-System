Other existing endpoints: GET /api/auth/csrf and POST /api/auth/logout. The client sends cookies with credentials: include, uses no-store, rejects fetch redirects, obtains a fresh CSRF token for every command and sends X-CSRF-TOKEN. These files and contracts were not modified.

No public registration, Remember Me request contract, account-lockout disclosure or new authentication workflow was found or invented. New-password validation remains 12–256 characters with matching confirmation. Current/confirmation passwords remain concealed; the existing primary password visibility toggle remains available for login and new-password forms.

## Implementation

- Shared authentication surface retains the supplied official crest and actual campus asset. No image edits, generation or replacement.
- Desktop composition remains photograph plus task panel, with a restrained 1.2:1 split and 400px task maximum. Forms do not gain a fixed height.
- Refined white task surface, charcoal typography and existing burgundy actions; existing warm-white/muted, gold, informational blue and validation-red roles remain available from V3.1.
- Brand separation uses 24px rhythm, 80px desktop/72px mobile logo width and the approved heading/body/meta weights and line heights. Mobile gutters are 16px; controls retain 44px minimum height and 8px label spacing.
- Password toggle alignment and control radii are consistent. Keyboard focus uses the approved blue ring; red validation remains distinct.
- AuthSurface is extracted from the existing AuthLayout and reused for the non-login session connection-error page. Its existing boundary condition, retry callback and refusal to render protected content are unchanged.
- Capability-denied presentation remains inside the V3.2 shell. Bootstrapping, auth transitions and business routing were not redesigned.
- No decorative motion, additional marketing copy, public activation button, new dependency or competing design system.
