# V2.3 — Premium application shell & global navigation

Status: implementation and automated gates complete; **authenticated browser verification remains pending private sign-in**. Not visually approved/frozen. Not committed or pushed.

## Scope and foundation

The persistent authenticated workspace supports the full SIAMIS platform, not only HR. V2.1 remains authoritative. Existing React Router, TanStack Query, API/session infrastructure, capability gates and backend authorization are unchanged. V2.2 authentication routes remain outside the shell.

## Navigation architecture

One module switcher plus current-module destinations replaces the overwhelming flat list/expanded planned inventory. Module metadata lists destination paths and filters them through existing visibleRoutes/capabilities. Modules with no usable permitted destinations are omitted. Switching navigates immediately to the first permitted existing destination; the route determines context.

Available context: Workspace, the existing School Management placeholder, Human Resources and Administration when Security.Manage permits it. Future metadata covers Admissions, Finance, Professional Development, Communication, Projects and Reports without invented routes or capabilities. School remains the existing honest placeholder; no student/academic pages are implemented. Future destinations can be added to metadata without another navigation system.

HR contains Overview, Employees, Attendance, Leave, Payroll and Documents, each retaining its current capability. Accounts & Security appears under Administration while its existing /hr/security URL and Security.Manage gate are preserved. Employment/lifecycle remains future destination work; no new page/route or permission is invented.

Legacy navigation metadata/helpers remain for compatibility/history. The new shell uses workspaceModules rather than displaying the old planned list. All pre-V2.3 navigation content, including F4 changes, is preserved as an exact prefix; only additive module presentation metadata/helpers were appended.

## Desktop / content frame

At 1024px and above, a persistent 240px sidebar preserves space for dense work. Official school crest is restrained; no campus hero. Navigation scrolls independently when it grows. Active destination uses aria-current, border, weight and restrained tint, separate from hover/focus.

The 64px compact sticky header shows module and destination plus the actual account affordance. The shared WorkspaceHeader supplies a compact h1, description and action slot above an unboxed, full-width content frame with V2.1 gutters. No redundant breadcrumb trail or forced content cards.

Desktop collapse was intentionally removed: the 240px navigation is already compact; icon-only group expansion/local-storage complexity was not useful for this checkpoint. Prior optional collapse storage is untouched and no new preferences are stored.

## Tablet / mobile

Below 1024px the content receives the full width. A shared Radix modal drawer opens from the header, using the same navigation metadata and components. Drawer width is bounded by viewport width; content scrolls independently, and touch targets remain 44px.

Radix preserves focus containment, Escape/backdrop dismissal and body scroll locking. Explicit selection closes the drawer; route/breakpoint changes remount it closed. Ordinary dismissal returns focus to the trigger; navigation close uses the existing main-content focus convention. Opening/closing does not unmount page content or introduce route animation.

## Account and logout

Actual username and existing account context remain available. The menu exposes the existing real Sign out action; unsupported Profile/Account settings options were removed. The existing logout handler, duplicate-command guard, busy status, failure/retry and cache/session behavior were preserved. No frontend-only redirect, account switching or impersonation.

## Capability and security boundaries

No role-name inference. Payroll.Read and HRDocuments.Read remain independent gates. Inaccessible destinations/modules are omitted, and manually entered routes continue through unchanged CapabilityRoute/ProtectedRoutes. Anonymous/error sessions cannot mount the shell. Public auth retains V2.2 and offline login semantics.

No backend, endpoints, auth contracts, capabilities, role grants, migrations, schema, seeds, account modifications or new dependencies. Real login/logout may write existing normal security audit/session records when the user signs in; no provisioning or account credential change is part of this task.

## Accessibility / interaction / honesty

Named navigation landmarks, skip-to-main, non-color-only active state, decorative icons, accessible switcher/account triggers, Radix keyboard menus/dialogs and V2.1 immediate blue focus are retained. Hover uses shared 120ms tokens; existing ui-floating opening-only motion and reduced-motion rules apply. No sliding/bouncing, animated routes, static-card lift or layout-dimension animation.

Reused Button, Avatar, WorkspaceHeader, existing Radix menu/dialog infrastructure, Lucide and V2.1 tokens. Shared primitives/tokens are unchanged; shell CSS is composition only.

No fake search, notifications, academic dates or unavailable header controls. The disconnected academic session and global-search ornaments were omitted until connected. No profile features or operational data were fabricated.
