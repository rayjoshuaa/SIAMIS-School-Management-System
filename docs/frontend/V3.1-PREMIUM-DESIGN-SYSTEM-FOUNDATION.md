## Scope and preservation

V3.1 extends the owned V2 components with selected shadcn-style composition patterns; it does not introduce another library. React, TypeScript, Vite, Tailwind, Radix and Lucide remain in place. No dependencies were added.

No production feature-page source, authentication/session/API code, capability grants/routing, backend source, EF model/migration, operational records or QA accounts were modified. F4, F5, F6, F7.1 and F7.2 source remains untouched. Shared presentation improvements flow through existing consumers; adoption of the new content frame/density contracts is opt-in. No Git commands, commits or pushes were performed.

The showcase is still on the existing Development-only route and excluded from the production router. Its records are explicitly synthetic constants. Its create demonstration validates locally and reports completion without appending a record, calling the API or persisting anything.

## Content and component contracts

`ContentFrame` owns outer gutters, max width and section spacing. A directly composed `WorkspaceHeader` adds no second outer inset or margin. Gutters are 16px mobile, 20px from 768px and 24px from 1280px. Consumers already inside a padded shell should deliberately remove duplicate outer gutters when they migrate; V3.2 owns shell adoption.

Optional `density="compact"` exists on the frame, button and metric strip. Defaults remain comfortable. The demonstration uses the compact frame and metrics; ordinary static surfaces do not acquire movement or new hover behavior.

Shared corrections:

- Label, checkbox, switch, radio group, table header/row/head and separator merge consumer classes with baseline classes.
- Button supports React 19 refs, including Radix trigger/close composition and focus restoration.
- Select forwards ID, invalid/required state and descriptions to its interactive trigger; styling can be supplied without leaking it into the root.
- FormField maintains 8px label/control spacing and 6px helper/error spacing; helpers use the metadata role.
- SystemState and EmptyState accept rich content without nested paragraphs.
- Tabs support optional contained horizontal scrolling; existing wrapping remains the default.
- Tables, pagination, filters, alerts, skeletons and existing empty/error states continue using the owned shared primitives.
- New composition styles remain in the components layer. Existing feature styles were not broadly moved or rewritten.

## Overlay contract

Existing Dialog/Sheet props, controlled/uncontrolled use, auto-focus callbacks and dismissible semantics remain supported.

| Pattern | Size prop    | Width             |
| ------- | ------------ | ----------------- |
| Modal   | sm / md / lg | 400 / 560 / 720px |
| Drawer  | md / lg      | 480 / 640px       |

Omitting size retains the existing 512px maximum for compatibility. Modals remain bounded by viewport margins; drawers fill the available narrow-screen width and viewport height. Header and optional footer stay outside the independently scrollable body. Safe action placement does not require a fixed form height.

`dirty` is an explicit consumer signal. Close, Escape and outside dismissal request an inline discard decision within the same dialog; there is no nested overlay. Keep Editing returns focus, and Discard closes through the existing change callback. Successful programmatic save/close remains controlled by the caller.

`pending` disables close and prevents Escape/outside dismissal. Consumers still own request execution and must disable mutating form controls and reject duplicate submissions. The demonstration does both. Existing `dismissible={false}` callers remain protected.

The showcase demonstrates initial focus on Record Name and explicit focus return for controlled modal/drawer openings without Radix Trigger elements. Legacy consumers are not automatically assigned dirty state or new submission logic.

AlertDialog remains the existing consequential-confirmation primitive. Existing feature forms using it are not migrated here; their workflow-specific changes belong to later phases.

## Limitations and V3.2 recommendations

- Product-owner visual approval is pending.
- Mobile tables use contained horizontal scrolling; they have not been replaced with feature-specific mobile record views.
- Production pages retain their current layouts and legacy spacing contracts until their own phases.
- Existing account/attendance overlays do not gain automatic dirty protection; adoption needs their real form state in the appropriate feature phase.
- No TanStack Table, Recharts, calendar library or second UI package was added.
- Original campus/logo assets were preserved; image optimization is deferred.

V3.2 should adopt ContentFrame into the authenticated shell, eliminate duplicated shell/header insets, deliberate tablet header/navigation density, and retain capability-aware module switching, logout, focus return and route protection. It must not use shell work to redesign operational page contents.
