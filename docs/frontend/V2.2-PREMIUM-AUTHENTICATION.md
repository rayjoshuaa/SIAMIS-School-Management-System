# V2.2 — Premium authentication experience

Status: **Authentication checkpoint accepted by the product owner. Final SIAMIS-wide visual polish is deferred. Local commit preparation approved; not pushed.**
Verified: 7 October 2026.

## Scope and authority

Presentation for Login, Activation, Forgot password, Reset password and existing forced password change. V2.1 remains the global school-platform design authority; committed F3 remains the authentication/security authority. No new dependencies, assets, routes, account mechanisms or operational data.

## F3 preserved / F3.5 superseded

The rejected F3.5 floating-card composition is replaced by an unboxed, aligned authentication task beside the real campus on desktop. Its useful semantic tests and first-input rather than heading focus remain. The historical F3.5 report is retained with a supersession note.

Session bootstrap, API payloads, credential-link capture/clearing, CSRF, cookie/session handling, logout, safe return URLs, 401 handling, capability enforcement, validation and account eligibility are unchanged. Routing, providers and API/auth libraries are untouched. Public activation, registration and Remember Me are absent.

## Composition and primitives

AuthLayout shares the unchanged official crest and campus assets across the family. Desktop separates bright institutional imagery from a warm neutral form surface; no floating card, decorative overlay, gradient, blur or shadow. A maximum 416px task keeps controls aligned. Tablet/mobile use a shallow campus band and top-aligned task.

Reused V2.1 Button, Input, FormField, Alert and SystemState. Typography, spacing, burgundy action, gold accent, blue focus, danger/error color, control height, radius and motion inherit existing tokens. Auth CSS handles composition only. V2.1 primitive files are unchanged.

## Login UX

Approved wording and username/password autocomplete remain. The password reveal action has a 44px target, accessible name/pressed state and retains focus/value without changing layout. Recovery remains the only public secondary account action.

Required errors stay beside their fields and do not submit or show an authentication alert. Credentials rejected by the existing engine show its unchanged safe message. Credential edits/retries clear stale login root errors. Forms grow naturally for feedback; there is no fixed error reserve.

## Activation and reset

Activation is titled “Set up your SIAMIS account”. Existing administrator-issued links and password rules remain authoritative. Missing links show a deliberate unavailable-link state and an administrator/recovery next step rather than a broken form. Server-rejected links retain the existing safe password-operation message; the client does not invent an expired-versus-invalid classification.

Existing new-password/confirmation contracts and mismatch validation remain. Completion is restrained: Account setup complete / Password updated, existing safe instructions and Back to sign in. Neither operation automatically authenticates.

## Recovery and forced password change

Recovery uses the existing verified email identifier and neutral non-disclosing response. Check your email is the completion heading. Back to sign in is explicit.

Forced password change uses the same family with the existing current/new/confirmation fields, refresh and sign-out behavior. Its authenticated guard and redirect remain unchanged.

## State hierarchy and submission

- Field errors: shared field association and danger presentation.
- Rejected operations: danger alert with unchanged safe text.
- API/network failure: informational connection alert with Service unavailable, not credential rejection.
- HTTP 429: warning retry guidance.
- Session expiry: informational status.
- Missing credential: configuration SystemState.
- Completion: success status.

Icons and text supplement color; errors announce via alert, completion via status. Buttons reuse loading presentation, retain height, disable duplicate commands and expose busy/status semantics. There are no blocking overlays.

## Responsive / accessibility / motion

Login reviewed in Chromium at 1440×900, 1280×800, 1024×768, 768×1024, 430×932 and 390×844. Desktop task fits without unnecessary scrolling; tablet/mobile preserve margins, natural cropping and touch targets. Recovery and missing-link states reviewed on desktop/mobile, with responsive DOM bounds checks across the same sizes.

Labels, error descriptions, autocomplete, semantic forms, heading non-focus, keyboard Tab/Space interaction, visible blue focus and masked passwords are preserved. Source images are decorative except the named crest. No layout animation or new motion; V2.1 timings and reduced-motion handling remain authoritative.
