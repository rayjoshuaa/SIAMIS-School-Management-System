## Scope and foundation

The authenticated shell adopts the approved V3.1 ContentFrame, WorkspaceHeader, typography, spacing, icon, focus and interaction roles. React, TypeScript, Vite, Tailwind, Radix and Lucide remain unchanged. No dependency was added. This checkpoint refines chrome and outer composition; feature workflows and their internal layouts remain intact.

## Shell changes

- Persistent sidebar: 224px from 1024px, 232px from 1280px; restrained 40px official crest, aligned school identity and compact module trigger.
- Module switcher keeps the existing capability-filtered destinations and Radix keyboard interaction. Removed its redundant Current module subtitle and replaced the repeated module-name navigation heading with Destinations.
- Destination controls retain at least 44px height, 18px navigation icons, restrained hover, an active burgundy edge/background and aria-current. Keyboard focus uses the V3.1 blue ring.
- Header uses a consistent approximately 60px height, one module-context line and the real account menu. The destination title belongs to the page header; no fake search, notifications, academic year or account actions were introduced.
- Account presentation uses a compact avatar, truncated long username with the full name available in the accessible trigger/menu, 14px primary text and 13px role/feedback text. Real logout, pending and failure handling are unchanged.
- Below 1024px the existing accessible drawer remains the navigation mechanism. No collapsed desktop mode or competing navigation system was added.

## Content ownership

The shell's main landmark has no outer padding. One ContentFrame owns responsive gutters (16/20/24px), the 24px section gap and page width. Its direct WorkspaceHeader has no second inset/margin. Features retain their own content spacing, filters, actions, tables, tabs, loading and error states.

- Operational workspaces: up to 1680px, fluid within available space.
- Employee 360 and attendance detail/review: reading width, up to 1280px.
- Employee create/edit/employment lifecycle forms: form width, up to 960px.

Width selection is presentation only. Route metadata, capability checks and authenticated boundaries were not changed. The skip link and focusable main landmark remain present.

## Limitations and V3.3 recommendations

- Product-owner visual approval remains required.
- Chromium was inspected; Firefox/WebKit and exhaustive screen-reader certification are not claimed.
- Dense feature filters and mobile tables retain existing wrapping/contained scrolling. Future feature-specific refinement needs separate approval.
- No new live logout or mutating HR workflow was performed; unchanged logout/mutation behavior is covered by existing regressions.
- Original branding assets remain unchanged; image optimization is deferred.
- Future route authors should explicitly choose workspace/reading/form composition. The current width choices cover existing routes without modifying their authorization contracts.

V3.3 should address separately approved feature-level action/header alignment, filter density and mobile record presentation using this shell foundation. It must preserve API semantics and avoid reintroducing outer page padding. V3.3 was not started.
